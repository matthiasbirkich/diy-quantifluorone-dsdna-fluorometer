# Appendices

The appendices provide practical reference material supporting the construction, calibration and routine operation of the DIY-QuantiFluorONE-dsDNA-Fluorometer. They complement the main chapters and are intended as a quick reference rather than a tutorial.

---

# Appendix A – File and Data Overview

The project uses several file types for firmware, calibration, measurements and validation.

| File | Purpose |
|------|---------|
| `quantifluorone_calibration` | Stores a calibration created directly on the fluorometer. |
| Calibration JSON | Transfers a calibration generated by the Calibration Suite to the instrument. |
| `quantifluorone_log_v100rc2.csv` | Measurement log generated by the firmware. |
| Calibration input CSV | Contains calibration standards used by the Calibration Suite. |
| Validation CSV files | Store raw, processed and statistical validation data. |

> **Note**
>
> File names may change in future firmware releases. The corresponding firmware documentation and software manifest always take precedence.

# Appendix B – Required Data Fields

## Calibration Input CSV

A calibration dataset should contain at least:

- Sample or standard identifier
- Known concentration
- Replicate number
- Measured fluorescence signal
- Blank information (if applicable)

## Measurement Log CSV

Typical measurement logs contain:

- Date and time
- Sample identifier
- Raw sensor values
- Calculated concentration
- Replicate statistics
- Calibration identifier
- LOD and LOQ (where available)
- Error or warning status

## Calibration JSON

A calibration file typically contains:

- Calibration model
- Regression coefficients
- Valid concentration range
- LOD
- LOQ
- Calibration uncertainty
- Calibration identifier
- Creation date

The exact field names are defined by the installed firmware version and Calibration Suite.

# Appendix C – Workshop Checklists

## Instrument Checklist

- [ ] PyBadge starts normally
- [ ] LED operates correctly
- [ ] TSL2591 detected
- [ ] Blank measurement successful
- [ ] Calibration loaded
- [ ] Quality-control standard accepted
- [ ] CSV logging operational

## Measurement Checklist

- [ ] Correct reagent
- [ ] Correct PCR tube
- [ ] Blank measured
- [ ] Calibration valid
- [ ] Sample mixed
- [ ] No visible air bubbles
- [ ] Sample within calibration range
- [ ] Replicate agreement acceptable
- [ ] Measurement stored successfully

# Appendix E – Repository Structure

The repository is organised into five principal components:

- **hardware/** – mechanical CAD models, PCB source files and wiring documentation
- **software/** – bootloader, CircuitPython and firmware releases
- **tools/** – calibration software and supporting utilities
- **validation/** – analytical validation datasets and evaluation scripts
- **docs/** – project documentation, figures and workshop booklet

This organisation separates hardware, software and documentation while maintaining complete traceability of all project components.
